# 2026-10-29

## 新增子项目 h3c-ops-agent（华三交换机批量运维 Agent）

需求：在 ops-manager 下新建子项目，能自动批量巡检华三交换机、配置标准团体名、自动接入 Zabbix 并监控、备份配置文件。

### 技术选型
- 依赖只用共享 venv 已有的 paramiko / requests / openpyxl，**没有引入 netmiko**，用 paramiko + invoke_shell 自己写 Comware 交互层（环境里 netmiko 未安装，少装一个依赖）
- 配置用 JSON（环境无 PyYAML），支持环境变量覆盖密码
- 包结构：`h3c_ops/{config,inventory,ssh,inspect,snmp,zabbix,backup,report,models,runner,cli}.py`，入口 `run.py`
- 命令：init / devices / inspect / snmp / zabbix / backup / full；默认预览，写操作需 `--apply`（+ 交互确认，`-y` 跳过）

### 关键实现决策
- 提示符正则由实际主机名动态生成（`<name>` / `[name-...]`），避免 `[Y/N]`、`[flash:/startup.cfg]` 被误判为提示符
- 主机名允许 `-`（`SW-Core-01` 这类很常见），login 若落在系统视图先 `return` 再识别
- 认证失败不重试（防账号锁定），只有网络类错误重试
- `save force` 只认回显**末尾**的提问，避免同一条回显里 `Continue? [Y/N]` 被应答两次
- 巡检可选命令（风扇/电源/温度/光模块）失败不记异常，部分型号不支持
- SNMP 幂等 + ACL 只补齐缺失规则；团体名用 `simple` 明文便于回读校验；不配写团体名
- Zabbix 先查后改，产出变更计划；同名主机 IP 不一致默认报冲突不覆盖；host.update 只做增量合并（组/模板/宏不丢）
- 备份：每次快照 + `latest.cfg` + unified diff + meta.json，保留 N 份；同秒多次备份自动加序号

### 验证
- `python -m unittest discover -s tests -t .` → 103 用例全绿，全部不依赖真实设备（SSH 层用假 channel 模拟）
- CLI 端到端：init / devices / full 预览 均跑通，生成 report.xlsx + summary.md + results.json + run.log

### 未验证
- 真实华三设备（无设备可连），SSH 层的分页、save 交互是按 Comware 回显规范模拟的
- Zabbix 真实 API（模板名、主机组需现场确认）
